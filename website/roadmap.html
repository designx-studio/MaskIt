Official product roadmap

From local redaction to AI Context Security Platform.

Sensitive context should be controlled before it reaches AI systems, agents, tools, and workflows. Maskit starts with the product that exists today and expands only when the policy foundation is reliable.

Phase 1, production readiness

0 to 3 months

Make current Maskit trustworthy.

Release automation, verified packages, versioning, installation and upgrade guides, security testing, detection explanations, false positive reduction, custom rules, policy separation, simulation, CLI and MCP quick starts, and honest Windows boundaries.

Phase 2, AI security control layer

3 to 6 months

Move from scanner to control layer.

Context classification, explainable risk scoring, signed policy bundles, file and repository protection, CI scanning, MCP permissions, and human approval workflows. Browser, Windows, CLI, CI, and MCP use one policy engine.

Phase 3, enterprise management

6 to 12 months

Manage policy without centralizing raw prompts.

Organization accounts, device enrollment, policy management, fleet visibility, security dashboard, evidence reporting, audit exports, user roles, and optional SSO. Raw prompts, clipboard contents, files, and secret values remain local by default.

Phase 4, AI agent security

12 to 18 months

Govern what agents can access and execute.

Local MCP security gateway, agent identity, tool permissions, repository boundaries, file access control, approval workflows, agent activity timeline, and tool trust scoring.

Build first

P0, policy foundation

Versioned context and evidence schemas, deterministic policy decisions, simulation, and parity fixtures.

P0, release trust

Verified artifacts, installation, upgrades, checksums, automatic website audits, and clear limitations.

P1, agent boundary

MCP gateway, permissions, repository scope, file filtering, approvals, and evidence without raw values.
